1. 文档目的

本文档用于确定 Life Alchemy 第一阶段 H5 Web App 的具体开发框架。它不是产品 PRD，而是偏工程落地的技术方案与边界约束文档。

本文重点解决以下问题：

  1. 项目使用什么技术栈；
  2. 前端、后端、数据库、存储、AI 分别怎么选型；
  3. 为什么后端选用 Python FastAPI；
  4. 项目目录结构如何设计；
  5. 数据库如何设计；
  6. API 接口如何划分；
  7. MVP 阶段做什么、不做什么；
  8. 哪些边界必须提前约束，防止项目范围失控。
核心决策：Life Alchemy 第一阶段采用 H5 Web App 快速验证路线，前端使用 Next.js，后端使用 FastAPI，数据库和存储使用 Supabase。

2. 项目开发目标

2.1 第一阶段目标

第一阶段目标是上线一个 H5 MVP，让真实用户可以通过链接访问并完成核心体验。

进入 H5 页面
  ↓
登录 / 匿名进入
  ↓
创建一颗宝石记录
  ↓
宝石进入水晶罐
  ↓
查看宝石详情
  ↓
点击“吃颗糖”抽取历史回忆
  ↓
AI 生成温暖鼓励语
  ↓
HP 回升
  ↓
查看本月成长统计

2.2 第一阶段不追求的目标

  • 不追求微信小程序第一时间上线；
  • 不做原生 App；
  • 不做复杂社交系统；
  • 不做大规模商业化；
  • 不做复杂 2D / 3D 物理引擎；
  • 不做完整 AI 陪伴人格；
  • 不做多端完全一致体验。

2.3 第一阶段重点验证

  1. 用户是否愿意记录；
  2. 宝石化记录是否有吸引力；
  3. 水晶罐首页是否有记忆点；
  4. AI 回忆回血是否有情绪价值；
  5. 这个产品是否值得继续做 PWA、微信小程序或 App。

3. 总体架构方案

3.1 最终架构

用户手机浏览器 / 微信内置浏览器
        ↓
Next.js H5 前端
        ↓
FastAPI 后端服务
        ↓
Supabase PostgreSQL
Supabase Storage
Supabase Auth
        ↓
LLM API

3.2 前后端职责划分

Next.js 前端负责

  • 页面展示；
  • 水晶罐交互；
  • 宝石动画；
  • 表单输入；
  • 图片预览与压缩；
  • 调用 FastAPI；
  • 移动端 H5 适配。

FastAPI 后端负责

  • 业务接口；
  • 用户身份校验；
  • 宝石创建与查询；
  • HP 计算；
  • 回忆抽取算法；
  • AI 模型调用；
  • 统计聚合；
  • 内容安全兜底。

3.3 为什么使用 FastAPI

Life Alchemy 不是纯 CRUD 项目，后续的核心竞争力会集中在 AI 反馈、情绪总结、回忆推荐、月报生成和个性化陪伴上。这些能力使用 Python 生态更自然。

  • FastAPI 适合快速构建清晰的 REST API；
  • Pydantic 适合做请求与响应模型校验；
  • Python 适合 AI、文本处理、统计分析和后续向量检索；
  • 接口文档可以自动生成，方便前后端联调；
  • 后端边界更清晰，不会和前端 Next.js 混在一起。
代价：FastAPI 方案比 Next.js API Routes 多一个后端服务，需要处理 CORS、部署、后端环境变量和服务监控。但长期维护性更好。

  • Redux：MVP 状态不复杂；

  • 微服务：当前业务规模不需要。

5. 系统边界约束

5.1 前端边界

前端负责用户体验，但不承载核心业务安全逻辑。

前端负责 前端不负责
页面展示、交互、动画 直接调用 AI API
水晶罐、宝石、HP 展示 保存敏感 API Key
表单输入、图片预览、调用后端接口 绕过权限查询其他用户数据
登录态展示和错误提示 决定最终 HP 和统计结果

5.2 后端边界

FastAPI 是项目业务中枢，负责所有可信逻辑。

后端负责 后端不做
用户身份校验 复杂实时通信
宝石 CRUD 多人在线互动
HP 计算与日志 支付系统
回忆抽取算法 复杂推荐系统
AI 调用与兜底 后台管理系统

5.3 数据库边界

数据库存储可信数据，不承载复杂 AI 或动画逻辑。

  • 存储用户资料、宝石记录、HP 日志、抽取日志、皮肤、成就、埋点；
  • 不存储未压缩大图原图；
  • 不存储无意义临时动画状态；
  • 所有用户私密数据必须按 user_id 隔离。

5.4 AI 边界

AI 只负责生成文字反馈，不负责决定业务状态。

  • AI 可以生成宝石标题、鼓励语、回血文案；
  • AI 不负责判断用户是否真实完成任务；
  • AI 不直接修改数据库；
  • AI 不做心理诊断；
  • AI 失败必须有兜底模板。

7. 数据库与存储设计

7.1 数据库选型

数据库使用 Supabase PostgreSQL。

FastAPI 访问数据库有两种方式：

方式 说明 推荐程度
SQLAlchemy 直连 Supabase Postgres 适合复杂查询、事务、业务逻辑 推荐作为主方式
Supabase Python SDK 适合 Auth、Storage、部分简单操作 辅助使用
推荐：数据库复杂业务使用 SQLAlchemy；Auth 和 Storage 使用 Supabase Python SDK 或 Supabase 相关接口。

7.2 核心数据表

表名 用途
profiles 用户业务资料
stones 宝石记录
hp_logs HP 变动日志
memory_draw_logs 回忆抽取日志
skins 系统皮肤配置
user_skins 用户已解锁皮肤
achievements 系统成就配置
user_achievements 用户已解锁成就
events 埋点事件

7.3 profiles 表

create table profiles (
  id uuid primary key references auth.users(id) on delete cascade,
  nickname text,
  avatar_url text,
  hp int not null default 80 check (hp >= 0 and hp <= 100),
  current_title text not null default '初级炼金师',
  current_skin_id text not null default 'default_crystal_jar',
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

7.4 stones 表

create table stones (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  type text not null check (type in ('strength', 'wisdom', 'charm', 'wealth', 'joy')),
  color text not null,
  content text not null,
  image_url text,
  ai_title text,
  ai_message text,
  rarity text not null default 'normal'
    check (rarity in ('normal', 'shiny', 'rare', 'legendary')),
  shape text not null default 'crystal',
  is_favorite boolean not null default false,
  draw_count int not null default 0,
  last_drawn_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now()
);

create index stones_user_id_idx on stones(user_id);
create index stones_user_created_idx on stones(user_id, created_at desc);
create index stones_user_type_idx on stones(user_id, type);
create index stones_favorite_idx on stones(user_id, is_favorite);

7.5 hp_logs 表

create table hp_logs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  change_value int not null,
  reason text not null,
  related_stone_id uuid references stones(id) on delete set null,
  hp_before int not null,
  hp_after int not null,
  created_at timestamptz not null default now()
);

7.6 memory_draw_logs 表

create table memory_draw_logs (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  stone_id uuid not null references stones(id) on delete cascade,
  ai_message text,
  hp_change int not null default 10,
  created_at timestamptz not null default now()
);

7.7 skins 与 user_skins

create table skins (
  id text primary key,
  name text not null,
  description text,
  image_url text,
  unlock_type text not null default 'default',
  unlock_value int,
  related_stone_type text,
  is_default boolean not null default false,
  created_at timestamptz not null default now()
);

create table user_skins (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id) on delete cascade,
  skin_id text not null references skins(id) on delete cascade,
  unlocked_at timestamptz not null default now(),
  unique(user_id, skin_id)
);

8. 鉴权与权限设计

8.1 鉴权选择

MVP 推荐使用 Supabase Auth。前端登录后拿到 access token，调用 FastAPI 时放入请求头。

Authorization: Bearer <supabase_access_token>

8.2 FastAPI 校验流程

前端请求 FastAPI
  ↓
FastAPI 读取 Authorization header
  ↓
校验 Supabase JWT
  ↓
解析 user_id
  ↓
业务接口只处理当前 user_id 的数据

8.3 MVP 登录方式

推荐优先级：

  1. 匿名登录；
  2. 邮箱魔法链接登录；
  3. Google / GitHub 登录；
  4. 后续再考虑微信登录。
推荐 MVP：匿名登录 + 后续绑定邮箱。这样首次体验门槛最低，用户打开链接即可创建第一颗宝石。

8.4 RLS 策略

所有用户私密数据表必须开启 RLS。

alter table stones enable row level security;

create policy "Users can view own stones"
on stones for select
using (auth.uid() = user_id);

create policy "Users can insert own stones"
on stones for insert
with check (auth.uid() = user_id);

create policy "Users can update own stones"
on stones for update
using (auth.uid() = user_id);

create policy "Users can delete own stones"
on stones for delete
using (auth.uid() = user_id);

8.5 权限原则

  • 用户只能读取自己的宝石；
  • 用户只能修改自己的资料；
  • 系统配置表可以公开读取；
  • FastAPI 中所有查询必须带 user_id；
  • Service Role Key 只允许后端使用。

9.2 统一响应结构

{
  "success": true,
  "data": {},
  "error": null
}

错误响应：

{
  "success": false,
  "data": null,
  "error": {
    "code": "STONE_NOT_FOUND",
    "message": "宝石不存在或无权访问"
  }
}

9.3 创建宝石接口

POST /stones

请求体：

{
  "type": "wisdom",
  "content": "今天学习了强化学习基础知识。",
  "image_url": "https://xxx.com/image.png"
}

服务端流程：

校验用户身份
  ↓
校验 type 和 content
  ↓
根据 type 计算 color
  ↓
计算 rarity 和 shape
  ↓
调用 AI 生成 ai_title 和 ai_message
  ↓
AI 失败则使用兜底文案
  ↓
写入 stones 表
  ↓
更新用户 HP
  ↓
写入 hp_logs
  ↓
检查是否解锁成就 / 皮肤
  ↓
返回新宝石

9.4 获取宝石列表接口

GET /stones?page=1&page_size=50&type=wisdom
  • 默认返回最近 50 条；
  • 不一次性返回所有历史数据；
  • 首页最多渲染最近 50 颗动态宝石。

9.5 抽取回忆接口

POST /memory/draw

服务端流程：

校验用户身份
  ↓
查询用户历史宝石
  ↓
过滤最近抽中过的宝石
  ↓
按权重随机抽取
  ↓
调用 AI 生成回血文案
  ↓
AI 失败使用兜底文案
  ↓
更新 stone.draw_count 和 last_drawn_at
  ↓
更新用户 HP
  ↓
写 hp_logs
  ↓
写 memory_draw_logs
  ↓
返回抽取结果

9.6 月度统计接口

GET /stats/monthly?month=2026-05

服务端计算：

  • 本月宝石总数；
  • 五类宝石数量；
  • 五类宝石占比；
  • 主导属性；
  • 成长评价；
  • 皮肤解锁进度。

9.7 上传签名接口

POST /upload/sign

用途：生成用户图片上传路径或签名 URL。MVP 也可以由前端直传 Supabase，但必须限制路径、大小和类型。

10. 核心业务规则

10.1 宝石类型

type 中文 颜色 HP
strength 力量 红色 +5
wisdom 智慧 蓝色 +5
charm 魅力 粉色 +5
wealth 财富 金色 +5
joy 小确幸 彩色 +8

10.2 HP 规则

行为 HP 变化
创建普通宝石 +5
创建小确幸宝石 +8
吃颗糖抽取回忆 +10
收藏宝石 +2
  • HP 最大 100；
  • HP 最小 0；
  • MVP 不做自动衰减；
  • 不做惩罚式扣分；
  • 后续再考虑长时间未记录的温和提醒。

10.3 稀有度规则

11. AI 方案

11.1 AI 调用原则

  • AI 必须由 FastAPI 服务端调用；
  • 前端禁止直接请求 LLM API；
  • LLM_API_KEY 只能存在后端环境变量；
  • AI 请求必须设置超时；
  • AI 失败不能阻塞创建宝石和回忆抽取主流程。

11.2 MVP AI 场景

  1. 创建宝石时生成 ai_title 和 ai_message；
  2. 吃颗糖时生成 memory ai_message。

11.3 暂不做的 AI 场景

  • AI 长聊天；
  • AI 心理咨询；
  • AI 年报；
  • AI 多轮记忆；
  • AI 主动推送；
  • AI 自动分析人格。

11.4 创建宝石 Prompt

你是一个温柔但不油腻的生活陪伴助手。
用户刚刚记录了一件生活小事。
请根据记录内容，生成一个简短标题和一句温暖鼓励语。

要求：
1. 标题不超过 12 个中文字符；
2. 鼓励语 20-50 个中文字符；
3. 不要说教；
4. 不要夸张鸡汤；
5. 不要诊断心理状态；
6. 不要提到你是 AI；
7. 语气温柔、具体、有陪伴感。

用户记录：{{content}}
宝石类型：{{typeLabel}}

请返回 JSON：
{
  "title": "",
  "message": ""
}

11.5 回忆回血 Prompt

你是一个温柔、克制、有陪伴感的生活陪伴助手。
用户正在回看一条过去的积极记录。
请基于这条记录，生成一句能让用户感到被支持的温暖话语。

要求：
1. 字数 20-60 个中文字符；
2. 不要过度鸡汤；
3. 不要说“你一定可以”；
4. 不要诊断心理问题；
5. 可以提醒用户：过去的自己曾经认真生活过；
6. 不要提到你是 AI。

过去的记录：{{content}}
宝石类型：{{typeLabel}}

请只输出一句话。

11.6 AI 兜底文案

类型 标题 鼓励语
力量 行动之光 你又为自己积累了一点行动的力量。
智慧 安静升级 你正在把新的知识，慢慢变成自己的东西。
魅力 发光时刻 你愿意表达和靠近世界，这本身就很珍贵。
财富 认真建设 你正在认真建设自己的生活。
小确幸 小小快乐 这份小小的快乐，值得被好好保存。

回忆回血兜底

这颗宝石提醒你，过去的你曾经认真生活过。今天也可以慢慢来。

11.7 内容安全边界

如果用户内容出现严重自伤、自杀、暴力等风险内容，系统不应输出普通鼓励语。

我很在意你现在的感受。如果你正处在危险中，
请马上联系身边可信任的人，或拨打当地紧急求助电话。
你不需要一个人扛着。

12.1 MVP 页面

12.2 MVP 不做页面

  • 好友页；
  • 聊天页；
  • 商城页；

  • 年报页；

  • 后台管理系统；
  • 运营活动页。

12.3 首页水晶罐边界

MVP 首页水晶罐只需要做到：

  • 展示最近 50 颗宝石；
  • 不同类型颜色不同；
  • 点击宝石查看详情；
  • 新宝石落入时有动画；
  • 点击或轻摇触发简单晃动；
  • 有 HP 条；
  • 有添加和吃颗糖按钮。

MVP 不做：

  • 真实复杂物理碰撞；
  • 3D 玻璃材质；
  • 所有宝石持续实时运动；
  • 宝石之间复杂堆叠计算；
  • 陀螺仪强依赖。

12.4 动画和性能边界

  • 首页动态宝石最多 50 颗；
  • 超过 50 颗的宝石转为静态背景点；
  • 动画只在用户操作时触发；
  • 不做全局持续粒子动画；
  • 首屏 JS 体积尽量控制；
  • Matter.js 如使用，必须动态加载；
  • 低端设备可以关闭复杂动画。

16. 质量、安全与风险

16.1 代码质量标准

  • 前端使用 TypeScript；
  • 后端使用 Python 类型注解；
  • FastAPI schema 使用 Pydantic；
  • 数据库字段使用 snake_case；
  • 前端变量使用 camelCase；
  • Prompt 集中管理；
  • 兜底文案集中管理；
  • 业务逻辑不写死在页面组件里。

16.2 用户体验标准

  • 首页 3 秒内可见主要内容；
  • 创建宝石流程不超过 4 步；
  • 创建失败要有明确提示；
  • AI 失败不能让用户卡住；
  • 空状态要有温柔文案；
  • 移动端按钮足够大；
  • 底部操作区不被浏览器工具栏遮挡。

16.3 数据安全标准

  • 用户记录默认私密；
  • 图片默认私密或签名访问；
  • AI Key 只能在后端；
  • Service Role Key 只能在后端；
  • 所有写接口必须校验用户身份；
  • 所有用户数据查询必须带 user_id；
  • Supabase RLS 必须开启。

16.4 主要风险与约束

风险 约束方案
水晶罐物理效果复杂 MVP 使用轻量动画，不强制真实物理引擎
AI 接口慢或失败 设置超时和兜底文案
Supabase 权限配置错误 所有用户表开启 RLS，并测试越权访问
功能范围失控 MVP 只围绕记录、宝石、水晶罐、回血、统计
产品变成压力打卡工具 不做断签惩罚，不做失败提示，不做排行榜
AI 过度心理咨询化 AI 只做温暖陪伴，不做诊断和治疗建议

17. 最终开发框架结论

Life Alchemy 第一阶段采用 H5 Web App 快速验证路线，后端选用 Python FastAPI。

17.1 最终技术框架

前端：
Next.js App Router
+ React
+ TypeScript
+ Tailwind CSS
+ Framer Motion

后端：
Python 3.12+
+ FastAPI
+ Pydantic
+ SQLAlchemy
+ Alembic
+ httpx

数据：
Supabase PostgreSQL
+ Supabase Auth
+ Supabase Storage

部署：
前端 Vercel
+ 后端 Render / Railway / Fly.io
+ 数据库 Supabase

17.2 核心边界

  1. MVP 只做 H5，不做微信小程序；
  2. MVP 只做核心记录闭环，不做社交和付费；
  3. 后端使用 FastAPI，承接业务逻辑、AI 调用和统计计算；
  4. AI 只做鼓励语和标题，不做聊天机器人；
  5. 水晶罐先做轻量动画，不做复杂 3D；
  6. 用户数据默认私密；
  7. 数据库结构要为后续 PWA 和微信小程序保持可迁移；
  8. 所有复杂能力都必须服务于核心体验，否则延后。
第一阶段最终交付物： 一个可以通过链接访问的 Life Alchemy H5 MVP。用户可以创建宝石、查看水晶罐、抽取回忆回血，并看到 AI 生成的温暖鼓励语。
